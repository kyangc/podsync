# 2026-10-19 媒体 Tunnel 握手故障

时间均为北京时间（UTC+8）。本记录不包含业务 ID、订阅地址、凭证或完整 Tunnel/connector ID。

## 已证实的故障边界

公开 RSS 正常、D1 节目为 visible、媒体源文件存在，nginx 源站可以读取；公开媒体请求仍返回 530/1033。旧样本曾命中陈旧缓存返回 206，但同一个旧样本从 NAS 或带唯一查询参数访问仍失败，不能据此判断服务已恢复。

12:02—12:07 的现场检查确认：

- connector 的 `/ready` 返回 503，`cloudflared_tunnel_ha_connections` 为 0。
- 长期运行的 connector 继续连接两个旧 Fake-IP，TLS 握手出现 EOF 或连接重置。同一 Docker 网络重新解析得到不同 Fake-IP，新解析目标可以建立 TLS 连接，旧目标立即 EOF。
- 默认解析器及显式查询公共 DNS 均返回 Fake-IP。仅在容器中指定公共 DNS，并不能假定已经绕过上游 DNS 处理。
- 仅重启 connector 后，发现地址已更新，但 QUIC 继续超时，公网仍失败。随后启动预检明确报告两组边缘目标的 UDP/QUIC 失败、TCP/HTTP/2 成功。

这些证据确认了旧 Fake-IP 不可用与 QUIC 路径不可用两个故障边界。旧映射为何失效、上游 Clash 的持久化和分流策略是否导致此事，仍需读取路由器配置及日志；尚不能归因到某个代理节点、订阅或防火墙规则。
