## 原因判断与边界

**已证实：** 三条远端路径在相邻时刻耗尽客户端请求期限，错误未包含 HTTP 状态、证书校验失败或响应解析失败。当前实现为每个幂等操作提供最多两次尝试、合计 30 秒预算；期限耗尽后保留告警、配置回退或持久化事件。错误本身不能确定当次尝试次数或停在哪个请求阶段。生产进程没有重启，后续调度和上报持续进行，不支持把本次归因于服务关闭时的全局 context cancellation。

**推断：** 同一 Worker 目标的配置、tombstone 和事件请求同时受影响，符合共享请求路径短暂阻塞；NAS 当前解析该目标仍使用 fake-IP，容器未配置显式代理环境变量。这不足以区分出口代理、上游网络、Cloudflare 边缘、Worker/D1 响应延迟或一条复用连接停滞，也不能直接套用 [6 日 TLS 握手故障](2026-10-06-nas-tls-retries.md) 或 [21 日媒体 Tunnel 故障](2026-10-21-media-tunnel-response-stall.md) 的根因。

**当前只读探针：** 在生产容器内使用原配置与凭证，以 Go 1.27.2 的默认 Transport 对公开健康、鉴权配置及鉴权 tombstone 各执行六次新建连接请求和六次复用连接请求，共 36 次。全部 HTTP 200、HTTP/2；复用组首个请求建连，其余 17 次确认复用。新建组 DNS 为约 1.6–4.3ms、TCP 0.3–1.2ms、TLS 268–336ms；全部请求总耗时约 0.21–0.84s。12 次配置响应均与已接受 cache 的 SHA-256 一致，共 28 个 feed。没有复现持续 DNS、TLS 或连接复用异常；这个当前样本不能反推昨晚的失败阶段。
